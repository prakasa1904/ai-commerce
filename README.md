# 🌾 Farm Marketplace

A fresh farm-to-table marketplace web app where local farmers sell and buyers shop **fresh produce, grains, dairy, and supplies** straight from local farms.

---

## What the product is

Farm Marketplace connects **farmers/sellers** who grow produce with **buyers** who want it — all in one seasonal marketplace:

- **Sellers** list their harvests in clearly defined **categories** (Vegetables, Fruits, Grains, Dairy, Livestock, Organic, Supplies) and can flag items for **wholesale** so resellers can buy in bulk.
- **Buyers** discover fresh items, filter by category or search by name, subscribe for weekly savings, and order wholesale by the kilogram.
- Prices are in **Indonesian Rupiah ("Rp X")** per kilogram (`/kg`).

## Architecture

The app is a full-stack product with a React SPA frontend and a Go backend:

```
┌─────────────┐   Vite proxy :5173    ┌──────────────┐   sqlite3    ┌──────────────────────┐
│  Browser    │ ───────── /api/* ───▶ │  Go Fiber    │ ───────────▶ │ farmer_marketplace.db │
│ (Vite dev)  │                       │  API :5001   │              │     (SQLite3)        │
└─────────────┘                       └──────────────┘              └──────────────────────┘
```

- **Frontend** (`src/`) — presentation modules (`modules/`), shared atoms/molecules, TanStack Query hooks, and API/client layers. Vite proxies `/api/*` to the Go backend on `:5001`.
- **Backend** (`server/`) — clean-architecture Go service in `internal/`. Feature-first layout (`internal/features/{user,shop,product,admin}`) with domain / usecase / repository / delivery-http layers, plus `internal/app` wiring, `internal/config`, and `internal/platform` infrastructure.
- **DB** — `farmer_marketplace.db` at the repo root. GORM `AutoMigrate` applies the schema; on start the backend runs legacy fixes (e.g. renames the `suplies` category) and seeds demo data when the users table is empty.

**Go migration status:** complete. The legacy `server/index.js` (Express) has been replaced by the Go service (`cmd/api`); `package.json` `start`/`seed` now run the Go entrypoints.

## API contract

The Go backend serves the following routes under `/api` (proxied by Vite):

```text
POST /api/auth/register           Register a user          → {user, token}
POST /api/auth/login              Login with credentials   → {user, token}
GET  /api/auth/me                 Current user + shops     → {user, shops[]} (Bearer)

GET  /api/products                Public product catalog   → {count, products[]}
GET  /api/cart                    Cart                     → {items:[]}   (hardcoded empty; not implemented)

GET  /api/admin/users             List users               (Bearer, admin)
POST /api/admin/users             Create user
GET  /api/admin/users/:id         Get user
PATCH /api/admin/users/:id        Update user
DELETE /api/admin/users/:id       Soft-delete user
POST /api/admin/users/:id/restore Restore user

GET  /api/admin/stats             Counts (users, shops, products, deleted rows)

GET  /api/admin/shops             List shops (self-scoped for non-admin)
POST /api/admin/shops             Create shop (owner = actor)
GET  /api/admin/shops/:id
PATCH /api/admin/shops/:id        Update shop
DELETE /api/admin/shops/:id       Soft-delete shop
POST /api/admin/shops/:id/restore Restore shop
GET  /api/admin/shops/:id/products    Products in a shop
GET  /api/admin/shops/:id/members     Shop memberships
POST /api/admin/shops/:id/members     Add member
PATCH /api/admin/shops/:id/members/:userId
DELETE /api/admin/shops/:id/members/:userId

GET  /api/admin/products          Admin product list (owner-scoped)
POST /api/admin/products          Create product
PATCH /api/admin/products/:id     Update product
DELETE /api/admin/products/:id    Soft-delete product
POST /api/admin/products/:id/restore Restore product
GET  /api/admin/products/:id/shops      Product → shop links
POST /api/admin/products/:id/shops/:shopId  Link product to shop
DELETE /api/admin/products/:id/shops/:shopId Unlink product from shop
```

Contract notes:

- **Auth:** `/api/admin/*` routes require a Bearer JWT (`Authorization: Bearer <token>`); missing or invalid tokens are rejected with an error response (`{error}`; currently surfaced as HTTP 500 by the default Fiber handler).
- **Soft delete + restore:** catalog objects are soft-deleted via `deleted_at` and can be restored via the `/restore` routes.
- **Error envelope:** all errors return `{error: "message"}`.
- **Register / Login** return `{user, token}`; timestamps are epoch-millis integers.

## What users can do

### 1. Discover products
- **Home page** — featured seasonal produce headline, category cards, product grid, and subscription/wholesale offers; filter by category and search by product name in real time.
- **Category page** — click any category card or pill to browse every product in that category (e.g. only Vegetables).
- **Product detail page** — view full description, price, wholesale status, and add to cart. *(Planned)*

The full flow: **Home → Category / Search → Product Detail → Add to Cart → Checkout**.

### 2. Buy in a category
- **Login / register** with email and password (shipped via the Go backend), then browse and manage a cart. *(Cart / checkout not yet implemented — see below.)*
- Run a search and category pills to browse exactly the category you want. Wholesale items are flagged with a **"Wholesale"** badge.

### 3. Sell in a category
- Logged-in sellers create listings assigned to a category (Vegetables, Fruits, Grains, Dairy, Livestock, Organic, Supplies) and can mark items as wholesale.
- Sellers can also run a **shop** on the platform (create a shop, manage members, link products to the shop) via the admin console.

### 4. Admin console
- Platform admins manage **users** (list, create, update, soft-delete / restore), **shops** (list, create, update, delete / restore, members), **products** (full CRUD + soft-delete / restore, shop links), and view **stats** (counts of users, shops, products, deleted rows).

### 5. Subscribe & go wholesale
- **Weekly subscriptions** — 15% off a recurring box of seasonal produce.
- **Wholesale** — resellers buy in bulk with an extra 5% off on orders over 100 kg.

## Getting started

From the repo root:

```bash
# 1. Seed the database (once — a no-op when users already exist)
cd server && DB_PATH=../farmer_marketplace.db go run ./cmd/seed
cd ..

# 2. Start the backend (:5001)
cd server && DB_PATH=$PWD/farmer_marketplace.db go run ./cmd/api
cd ..

# 3. Start the frontend (:5173) in a second terminal
npm run dev
```

Open http://localhost:5173. The Vite dev server proxies `/api/*` to `localhost:5001`, so the app talks to the Go backend with no extra setup.

### Build (frontend)

```bash
npm run build
```

### Environment variables (Go backend, `server/internal/config/config.go`)

| Variable | Default | Purpose |
|---|---|---|
| `PORT` | `5001` | HTTP listen port |
| `DB_PATH` | `farmer_marketplace.db` | SQLite database path (relative to `server/`) |
| `JWT_SECRET` | `farm-marketplace-dev-secret` | Secret used to sign JWTs (dev fallback) |
| `JWT_EXPIRES_IN` | `7d` | JWT lifetime (`1h` / `24h` / `7d`) |
| `APP_ENV` | `development` | Logging environment (`development` / `production`) |

For a fresh DB, delete `farmer_marketplace.db` and re-run the seed.
